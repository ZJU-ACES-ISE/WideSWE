Enhance the Azure Event Hub input with RBAC authorization through OAuth2 client secret authentication. Previously it only supported shared access key authentication with a connection string. Add an `auth_type` parameter so users can select `connection_string` or `client_secret`; when it is omitted, default to `connection_string` for backward compatibility. Require `connection_string` for connection-string authentication, and reject unsupported authentication types.

For client-secret authentication, require `eventhub_namespace` as the fully qualified namespace, `tenant_id`, `client_id`, and `client_secret`. Support `authority_host` values for Azure Public Cloud (`https://login.microsoftonline.com`), Azure Government (`https://login.microsoftonline.us`), and Azure China (`https://login.chinacloudapi.cn`); an empty or unsupported value defaults to Azure Public Cloud. Use the same authentication type for both Event Hub and the storage account. Continue to support processor versions `v1` and `v2`: `v1` requires `storage_account_key` for either authentication type; with `v2`, connection-string authentication needs a storage account connection string supplied directly or constructed from `storage_account` and `storage_account_key`, while client-secret authentication reuses the same credentials for storage and does not require a storage account connection string.

Add the same client-secret authentication support to Azure integrations that use Event Hub. Expose the new authentication fields, make connection-string and storage-key fields conditionally required according to `auth_type`, and render the selected authentication settings in generated input policies. Existing or default connection-string configurations must explicitly emit `auth_type: connection_string`, while client-secret configurations must emit the OAuth2 fields.
