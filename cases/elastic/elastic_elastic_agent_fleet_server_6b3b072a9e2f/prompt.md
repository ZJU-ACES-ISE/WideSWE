Add end-to-end gzip compression support for Fleet checkin requests. Add a `fleet.checkin.compression` setting with `none` and `gzip` as the supported values, defaulting to `gzip`. With `gzip`, checkin request bodies must be gzip-compressed and sent with `Content-Encoding: gzip`; with `none`, they must remain uncompressed and omit that header. Preserve an explicitly configured value through enrollment and subsequent restarts. Checkin body sizes can be large and are expected to grow as the Fleet API mirrors attributes from the OpAMP protocol, specifically `effective_config`.

Fleet Server must accept valid gzip-encoded checkin requests and process them with the same semantics as uncompressed checkins. Include gzip request encoding in the checkin API contract, and return a bad-request response when a request declares `Content-Encoding: gzip` but does not contain a valid gzip body.
