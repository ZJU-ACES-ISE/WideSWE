Support qualified input names for composable integration packages. With OTel integrations, a policy template can contain multiple inputs with the same `type`, and data streams that refer to them only by type cannot distinguish between them. This can produce ambiguous policies, mixed UI elements, missing stream templates, or failures to create policies correctly.

Starting with `format_version` 3.6.0, allow `policy_templates[].inputs[].name` as an optional input qualifier. When a name is present, the corresponding data streams must reference it through `streams[].input`, while `type` remains the actual agent input type. If a policy template contains multiple inputs with the same type, require a stable, unique name for each of them. When no qualifier is needed or present, preserve the existing type-based behavior.

Composable packages with `requires.input` can have multiple required inputs of the same `type`. Their built policies must resolve bundled package references and preserve the matching input names and stream references. Fleet must allow explicitly named inputs of the same type to coexist and let data streams reference them unambiguously. When an integration is bundled with inputs, API reference documentation must use the effective name instead of the input type.
