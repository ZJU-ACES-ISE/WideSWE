Support consistent Cloud ID parsing and service targeting. A few places need to decode the Cloud ID into its constituent parts, including the Elasticsearch URL, Kibana URL, host, and default port. Expose the decoded components from the common browser and server cloud contracts as `elasticsearchUrl`, `kibanaUrl`, `cloudHost`, and `cloudDefaultPort`, so existing consumers can use the shared cloud contract.

Extend `CloudNodePool.ParseCloudId` to support the format `host:port$esId:esPort$kbId:kbPort` and allow the same Cloud ID to target either Elasticsearch or Kibana through `CloudService.Elasticsearch` and `CloudService.Kibana`. A service-specific port overrides the host port; otherwise use the host port, or port 443 when no port is provided. Elasticsearch-only Cloud IDs remain valid for Elasticsearch, while targeting Kibana requires a non-empty Kibana identifier. Empty or malformed Cloud IDs must be rejected according to the existing failure convention of the API.

Add `CloudService` constructor overloads to `CloudNodePool`, `TransportConfiguration`, `TransportConfigurationDescriptor`, and `ElasticsearchConfiguration`. Preserve all existing constructors and existing Elasticsearch-targeting behavior to avoid breaking current consumers.
