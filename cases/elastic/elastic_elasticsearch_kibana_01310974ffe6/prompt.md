EIS authorization response now includes a `removed_endpoints` list of the endpoint IDs that were removed. Add `removed_endpoints` to the authorization response. When the `AuthorizationPoller` detects that an existing endpoint's ID is in the `removed_endpoints` of the most recent authorization response, it deletes it. Treat a missing `removed_endpoints` field as an empty list, handle duplicate IDs once, and ignore removed endpoint IDs that do not exist locally.

Unregister connectors when their inference endpoint is removed. Elasticsearch can now delete preconfigured inference endpoints that have been marked end-of-life by the Elastic Inference Service. Previously, once a dynamic inference connector was registered, Kibana kept it in memory indefinitely, so an endpoint deleted by Elasticsearch would leave a stale `.inference` connector pointing at a non-existent `inferenceId`.

Add `unregisterDynamicConnector(connectorId)` to the actions plugin start contract. It removes only entries with `isDynamic === true` and reports whether a connector was removed, so preconfigured and system connectors are protected. When refreshing inference endpoints, unregister stale dynamic `.inference` connectors whose configured `inferenceId` no longer corresponds to an eligible endpoint; leave other connector types and dynamic connectors without an `inferenceId` unchanged.
