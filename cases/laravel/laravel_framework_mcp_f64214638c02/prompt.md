Introduce PHP 8 Attributes as a non-breaking alternative to class properties for configuration.

Over the last few years more attributes have been added, but properties are still documented for various things, leading to an inconsistent state where attributes are used for some things and properties for others.

Add attribute support for configuring Eloquent models, queue jobs, event listeners, notifications, mailables, broadcast events, Artisan commands, form requests, test seeders, factories, and API resources. Public attributes include `Appends`, `Connection`, `Fillable`, `Guarded`, `Hidden`, `Table`, `Touches`, `Unguarded`, `Visible`, `Backoff`, `DeleteWhenMissingModels`, `FailOnTimeout`, `MaxExceptions`, `Queue`, `Timeout`, `Tries`, `UniqueFor`, `Signature`, `Description`, `RedirectTo`, `RedirectToRoute`, `StopOnFirstFailure`, `Seed`, `Seeder`, `UseModel`, `Collects`, and `PreserveKeys`. `Table` should also cover primary key, key type, incrementing, timestamps, and date format configuration. All attributes are optional; explicitly configured existing class properties remain authoritative so the feature is fully backward compatible.

Following the same Laravel ecosystem direction, add attribute alternatives for MCP primitives and servers. Support `Name`, `Title`, `Description`, `Uri`, `MimeType`, `Version`, and `Instructions`, and make primitive, resource, and server accessors check attributes first, then fall back to properties, then to auto-generated defaults. Attributes should be inherited, with a child attribute overriding its parent, and resolved values should appear in array representations. A resource implementing a URI template should continue to use that template instead of a `Uri` attribute, and existing defaults such as `text/plain` for a missing MIME type should remain unchanged.
