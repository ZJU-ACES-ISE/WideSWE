Add Queryable Encryption support.

Queryable Encryption allows sensitive fields in the database to be encrypted while still being queryable. It can be used with MongoDB replica sets or sharded clusters running version 7.0 or later; standalone instances are not supported. The `supports_queryable_encryption` database feature requires MongoDB 8.0 or later, a replica set or sharded cluster, and MongoDB Atlas or Enterprise.

Support encrypted database configuration through `AutoEncryptionOpts` and provider-specific `KMS_CREDENTIALS`. Provide encrypted field variants for arrays, embedded models, binary/boolean/string/date/time/decimal/duration/float/integer/IP/ObjectId/URL/UUID values, including public classes such as `EncryptedArrayField`, `EncryptedEmbeddedModelField`, `EncryptedEmbeddedModelArrayField`, `EncryptedCharField`, `EncryptedDateField`, `EncryptedDateTimeField`, `EncryptedDecimalField`, `EncryptedIntegerField`, `EncryptedObjectIdField`, and `EncryptedUUIDField`. Scalar fields should accept `queries` metadata with the supported `equality` or `range` query type; array and embedded-model encrypted fields should not accept `queries`. Encrypted fields should reject `db_index=True`, `null=True`, and `unique=True`.

Migrations should create or reuse data encryption keys and produce encrypted field metadata containing `path`, `bsonType`, `keyId`, and optional `queries`. The `showencryptedfieldsmap --database` command should emit a map suitable for `AutoEncryptionOpts.encrypted_fields_map` and report missing encryption keys clearly. Supported equality and range lookups should work through the ORM, while unsupported encrypted operations such as field-to-field comparisons, unsupported aggregation/group/lookup/union operations, and multi-document updates should be rejected rather than producing invalid queries.

Use the shared lib for mongocrypt included in the `pymongocrypt` wheel. Also account for the command casing issue discovered during this work: the server accepts either `buildInfo` or `buildinfo`, but the crypt command bypass must handle both forms.
